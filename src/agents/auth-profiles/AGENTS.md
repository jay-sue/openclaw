# src/agents/auth-profiles

多认证 profile 管理模块，负责凭据存储、OAuth 刷新、轮询排序、冷却/禁用机制与诊断修复。

## 类型与常量


| 文件             | 功能                                                                                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types.ts`     | 核心类型：`ApiKeyCredential`、`TokenCredential`、`OAuthCredential` 三种凭据，`AuthProfileStore` 存储结构（profiles/order/lastGood/usageStats），`ProfileUsageStats` 使用统计，`AuthProfileFailureReason` 失败原因枚举 |
| `constants.ts` | 模块常量：存储版本号、文件名（`auth-profiles.json` / `auth.json`）、外部 CLI profile ID、文件锁重试配置、外部 CLI 同步 TTL、子系统日志实例                                                                                      |


## 文件路径与存储


| 文件         | 功能                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| `paths.ts` | 解析认证存储文件路径（主路径/旧格式路径/展示路径），确保存储文件存在                                                                     |
| `store.ts` | 认证存储核心读写层：加载/解析/保存 `auth-profiles.json`，兼容旧版 `auth.json` 自动迁移，运行时内存快照，合并主代理与子代理存储，带文件锁的原子更新，保存时自动清除明文密钥 |


## Profile 管理


| 文件            | 功能                                                        |
| ------------- | --------------------------------------------------------- |
| `profiles.ts` | Profile CRUD：创建/更新（含密钥标准化）、按 provider 列出、设置排序、标记"上次成功"、去重 |
| `display.ts`  | UI 显示辅助：根据 email 信息生成可读标签（`profileId (email)`）            |


## OAuth 与凭据解析


| 文件                    | 功能                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oauth.ts`            | OAuth 凭据解析核心：按类型（api_key/token/oauth）解析 API Key，支持 SecretRef 引用解析、OAuth token 过期自动刷新（带文件锁）、子代理继承主代理凭据、Codex refresh 降级、legacy profile ID fallback |
| `credential-state.ts` | 凭据状态评估：判断 token 过期状态，评估各类型凭据是否可用（key/token/access 存在性、过期、SecretRef）                                                                               |


## 使用统计与冷却


| 文件         | 功能                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------- |
| `usage.ts` | 冷却机制核心：判断冷却状态、标记成功/失败（指数退避）、清除冷却、清理过期冷却、推断不可用原因、获取最早冷却到期时间。billing/auth_permanent 用长周期禁用，一般错误用短周期冷却 |


## Profile 排序


| 文件         | 功能                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `order.ts` | 排序与轮询：按配置/存储的显式排序或自动发现确定使用顺序，支持 eligibility 过滤、冷却 profile 排末尾、round-robin（类型优先级 oauth > token > api_key，再按 lastUsed 最旧优先）、preferredProfile 优先 |


## 会话覆盖


| 文件                    | 功能                                                                      |
| --------------------- | ----------------------------------------------------------------------- |
| `session-override.ts` | 会话级 auth profile 覆盖：按会话状态（新会话/压缩次数/冷却）自动选择或轮转 profile，支持用户手动指定和自动轮转两种模式 |


## 外部 CLI 同步


| 文件                     | 功能                                                                    |
| ---------------------- | --------------------------------------------------------------------- |
| `external-cli-sync.ts` | 从外部 CLI（Qwen Code CLI、MiniMax CLI）同步 OAuth 凭据：本地凭据缺失/过期时自动更新，带 TTL 缓存 |


## 诊断与修复


| 文件          | 功能                                                                                        |
| ----------- | ----------------------------------------------------------------------------------------- |
| `doctor.ts` | 认证诊断提示：检测 Anthropic OAuth 刷新失败时的 legacy profile ID 漂移，生成诊断信息引导 `openclaw doctor --yes` 修复 |
| `repair.ts` | Profile ID 漂移修复：通过 email/lastGood/命名启发式为旧版 `provider:default` 找到新 OAuth profile，执行配置迁移    |


## 状态观测


| 文件                     | 功能                                             |
| ---------------------- | ---------------------------------------------- |
| `state-observation.ts` | 失败状态变更结构化日志：记录错误计数、冷却/禁用窗口变化，脱敏 profile ID 后输出 |
